# SwingCue 项目文档集 (Documentation Set)

> 本目录是 SwingCue / 人体动作平台项目的**中央档案库**。所有战略、架构、纪律、阶段进展、规格、真值、会话记录都归档在此,并**随每个阶段持续更新**。

## 目录结构

| 目录 | 内容 | 更新频率 |
|---|---|---|
| `00_BLUEPRINT/` | 项目最高层蓝图(战略/架构/路线图) | 重大战略调整时(版本号递增) |
| `01_ARCHITECTURE/` | 三层架构、数据契约、资产搬迁映射 | 架构变动时 |
| `02_DISCIPLINE/` | 铁律与工作纪律(GT铁律/数据来源/授权) | 稳定,极少改 |
| `03_STAGE_LOG/` | 每个阶段的进展日志 | **每阶段持续更新** |
| `04_CHECKLISTS/` | 每个阶段的检查清单 | **每阶段持续更新** |
| `05_ENGINE_SPECS/` | 引擎/特征/模块规格文档 | 开发中随时新增 |
| `06_GT_LABELS/` | 人工确认的真值(Ground Truth)档案 | 每次人工确认后更新 |
| `07_SESSION_NOTES/` | 每次重要工作会话的要点记录 | 每次重要讨论后新增 |

## 使用约定

1. **蓝图是最高准则**:任何具体开发与蓝图冲突时,以蓝图战略方向为准(`00_BLUEPRINT/`)。
2. **每阶段收尾必更新**:进入或完成一个阶段时,更新对应的 `03_STAGE_LOG/` 和 `04_CHECKLISTS/`。
3. **纪律不可绕过**:`02_DISCIPLINE/` 里的铁律(尤其 GT 铁律、授权红线)在任何情况下不可违反。
4. **文档为王**:项目状态活在这些文档和 git 里,不依赖任何单机或单次对话记忆。
5. **每次工作后**:`git add . && git commit && git push` 同步到远程私库。
