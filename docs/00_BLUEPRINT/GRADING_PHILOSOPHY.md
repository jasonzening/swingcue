# SwingCue 判定哲学纲领(Grading Philosophy)

> **本文件是所有 cue 判定逻辑的统领原则。** 任何新 cue 的判据设计、阈值设定、指示器分级,都必须遵循本纲领。与本纲领冲突的旧判据以本纲领为准。
> **状态:v1.0 框架版。** 分级带(尤其黄带)的具体数值边界标注为"待真实数据校准",不得当作已定死的生产阈值。
> 来源:全网权威检索(Stanford benchmark 研究、TPI、HackMotion、Sportsbox AI 竞品分析)+ Jason 裁决 2026-07-16。
> 最后更新:2026-07-16 · 更新人:Claude(Jason 验收)

## 一、核心问题与转向

### 问题
早期判定体系是**二元阈值**:某信号超过一条线 = 报错,否则 = 无错。这对初学者够用(初学者多为大毛病),但存在根本天花板:

- 挥杆错误**不是二元的(有/没有),而是连续的程度问题**。
- 越到中级,问题越细微;而恰恰是这些细微差距,决定了能否突破瓶颈。
- 二元阈值对"差一点点"只能给"要么报要么不报",无法告诉中级球友"你已经很好、只差 5°"——而这正是帮中级进步的最关键信息。

### 科学依据(Stanford Benchmark 研究,Jessica Rose et al.)
- 职业球员动作高度一致:峰值 X-factor 变异仅约 7.4%,某些相位职业之间几乎无法区分。
- 业余球员的偏差**随差点连续递增**:落在职业均值 1–2 个标准差之外的因素数量,随水平下降而增多。
- 连差点 30 的业余和新手,X-factor 也有 46–48°,离职业的约 56° 不是"有没有"的问题,而是"差多少"。
- 结论:**错误是连续的偏离,不是二元的有无。** 这是本纲领的科学基石。

### 商业依据(竞品 Sportsbox AI)
- 最领先竞品的产品核心正是"细微差距"的量化:不说"你错了",而是给**百分位**(如速度分 86 = 比 86% 同组球员快)。
- 允许教练**设定目标范围**给中级球友即时反馈(如"上杆再多转一点")。
- 顶级球员(如用其调骨盆细节的案例)用它抠的正是"微小但关键"的差距。
- 但其呈现是大量 3D 数字,普通业余常看不懂。**SwingCue 的差异化机会:把复杂度藏起来,只给直观的分级视觉。**

### 转向
**从"错误检测(二元)"转向"偏离度量(连续)+ 分级带(直观)"。**

> 一句话原则:**不判定"对/错",而是度量"你在这个动作上,偏离理想基准多远,处于什么水平带"。**

## 二、三层判定结构

所有 cue 的判定统一采用三层结构。

### 第一层:连续偏离量(替代二元阈值)
- 每个信号不再判"超没超线",而是算它**偏离理想基准多少**。
- 理想基准来自权威文献(见各判据卡)。示例:头漂理想 = 0(容差 ±1.5 英寸);肩转理想 ≈ 90°;X-factor 理想 ≈ 40–45°。
- 用户实测值与理想基准的距离 = 连续偏离量。
- 意义:同一个用户,不同错误的严重程度可能天差地别(例:某用户头漂偏离巨大、肩转偏离中等、X-factor 偏离很小),二元阈值体现不出,偏离量可以。

### 第二层:水平带分级(给"细微"一个意义)
将偏离量映射到三个带:

| 带 | 含义 | 主要服务对象 |
|---|---|---|
| 🟢 绿带 | 在理想 ± 容差内 = 这个动作没问题 | 全体 |
| 🟡 黄带 | 轻微偏离 = "已经不错,再优化一点会更好" | **中级球友(关键带)** |
| 🔴 红带 | 明显偏离 = 明确错误 | 初学者主要落此 |

- **黄带是抓中级球友的关键区间。** 二元系统看不见它;分级系统能。
- **v1 状态:三级框架全部搭建,但黄带的具体数值边界标注"待真实数据校准"。** 原因:当前仅有刻意做出的测试视频,用它定黄带边界会失真。黄带边界需等真实中级球友数据积累(data flywheel)后校准。

### 第三层:置信度门控(诚实标注可靠性)
- 不是每个信号都能测准。判定必须诚实标注每个信号的可靠性上限。
- 接入既有三级确定性系统(Possible / Likely / Confirmed)。
- face-on 可靠测量的信号(如头部横移)→ 绿黄红分级可信。
- face-on 欠定的信号(如深度方向旋转)→ 只能给粗分级,且证据等级封顶 Likely。

## 三、按信号类型分定精度(诚实边界)

**关键约束:2D face-on 测"细微差距"的精度有物理上限,必须按信号类型分开定判定精度,不得假装能测测不准的东西。**

竞品能做精细百分位,依赖 3D 重建 + 数千次挥杆数据库。SwingCue 当前是 face-on 2D 单机位。因此:

| 信号类型 | 例子 | 2D 可测性 | 可做到的判定精度 |
|---|---|---|---|
| 画面内平移/角度 | 头部横移、手臂弯曲角 | 高(画面平面内,不吃前缩亏) | 连续偏离 + 黄带,可服务中级 |
| 需投影校正的角度 | 手臂弯曲(顶点前缩) | 中(需前缩校正指标) | 联合信号 + 粗分级 |
| 深度方向旋转 | 转肩、X-factor | 低(纯 RGB 无深度,旋转欠定) | 仅粗分级(明显不足/大致够),封顶 Likely,**做不了细微** |

- **误导中级用户比不报更糟。** 若某信号 2D 测不准细微差距,就诚实只给粗分级,不伪装精度。
- 深度旋转类信号若要做到细微精度,迟早需要 3D 或 DTL 第二机位——这是已知的未来扩展方向,不在 v1 承诺内。

## 四、商业定位含义

- SwingCue 的差异化**不是**"比竞品更准的 3D"(重资产军备竞赛,非当前优势)。
- 差异化是:**用极简视觉 + face-on 单机位,把"能可靠测的那几个动作"的偏离度,做成初学者和中级都秒懂的绿/黄/红分级反馈。**
- 这是"卡路里 app"哲学的兑现:把复杂度藏在后台,前台只给一个直观的带。
- 护城河(AI 自动判断 + 极简指示器)+ 分级带,比竞品的一堆数字更适合大众。

## 五、对现有 cue 的约束

所有已封板和在建 cue 需按本纲领复核:

| cue | 2D 可测性 | v1 判定方式 | 能否服务中级 |
|---|---|---|---|
| 头部漂移 | 高 | 连续偏离 + 绿黄红带,容差 1.5 英寸 | ✓ 能测细微 |
| 手臂弯曲 | 中(需前缩校正) | AB-angle + AB-fore 联合 + 分级 | 部分,粗分级 |
| 转肩不足 | 低(深度欠定) | 仅粗分级(明显不足/大致够),封顶 Likely | ✗ 测不了细微,诚实标注 |
| Slide/Sway(已封板) | 中 | 待按本纲领复核是否补分级 | 待评估 |
| Chicken Wing(已封板) | 中 | 待按本纲领复核是否补分级 | 待评估 |
