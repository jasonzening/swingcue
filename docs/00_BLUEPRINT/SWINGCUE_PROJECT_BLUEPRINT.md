## 第一部分:战略定位

### 1.1 一句话定义

**对外(用户/投资人/官网):**
> **SwingCue turns movement video into one clear visual cue for your next swing.**
> SwingCue 把一段动作视频,变成你下一杆就能照着做的一个视觉 cue。

**平台级:** *An AI motion cue platform that helps people move better, one cue at a time.*

**内部(蓝图定义):** 一个**可插拔的人体动作理解与反馈平台**。SwingCue(高尔夫)是验证平台、并率先落地的第一个行业包。核心能力:把复杂难懂的运动技术,转化为面向初/中级、零学习成本、一眼看懂的**视觉 cue**,并通过教练参与的数据飞轮持续变准。换一个"行业包"即可复制到网球、滑雪、健身、康复理疗等任何人体动作领域。

### 1.2 平台是战略终局,高尔夫是执行优先级(v2.2 修订 — 重要)

> 修订说明:v2.0 的"平台优先而非高尔夫优先"与"不要过早抽象、先做深高尔夫"存在冲突,易被误读为"现在就搭跨行业框架"。v2.2 纠正如下。

- **平台是战略终局**:公司级价值在于可插拔的人体动作平台,而非又一个高尔夫 app。
- **高尔夫是执行优先级**:当前不同时做多个运动,也不先抽象通用行业包,而是用高尔夫把三层架构、参考对比、视觉 cue、教练飞轮完整跑通一遍。
- 只有当第二个行业真正进入时,才正式抽象通用接口。
- 两个必须避免的错误:① 过早平台化(无第二行业验证就设计通用框架);② 高尔夫没做深就想复制。

### 1.3 为什么这个定位成立(竞品结构性空白)

高尔夫单一垂直已拥挤且有强对手(GOATY/Sportsbox)。若自我定义为"高尔夫 app",将与已成型、已有飞轮的对手正面硬刚,处追赶位。但无任何竞品占住"真正可插拔的多行业人体动作平台"——GOATY 高尔夫专用;Sportsbox 重心高尔夫;多运动 app 是浅层拼接。学术上 CoachMe(ACL 2025)已证"通用底座 + 少量数据换行业"可行,却无人产品化。这个空位是我们的护城河,且是竞品架构上做不到的。

### 1.4 核心产品范式:Next-Swing Loop(下一杆闭环)(v2.2 新增 — 核心)

> SwingCue 不是"分析报告工具(analyzer)",而是"动作改变引擎(change engine)"。价值不在一次说出多少问题,而在让用户下一杆真的动得更好。

最小闭环(产品灵魂):
1. 用户拍一杆
2. 系统判断视频是否可分析(不可则引导重拍)
3. 只选择 ONE 个最高置信、最值得先改的问题
4. 给 ONE 个一眼看懂的视觉 cue(+ 可选一个 15 秒 drill/feel)
5. 用户照着 cue 再拍一杆
6. 系统验证动作是否朝正确方向改善,并告诉他"变好了多少"

One issue → one cue → one verification. 这比"你有 8 个错误、得分 6.3"更适合初/中级用户,也比"卡路里 App 式结果识别"更有杀伤力——我们做的是动作改变,不是结果识别。

### 1.5 三条差异化护城河

"用摄像头抓关节点做反馈"是行业标配,非壁垒。真正壁垒:
1. **可插拔多行业平台**(最核心)——三层架构,换行业包即可复制。竞品无一具备。
2. **视觉直观 + 初学者友好 + 下一杆闭环**——不给数字/术语/职业标准吓人;以三层基准出发,不用单一职业模板。直击竞品"给数字不给指导、学习曲线陡"的痛点。
3. **教练配对 + 拖拽标注 + cue 有效性的"人在环"飞轮**——高纯度、合规、可追溯。区别于纯算法飞轮。

### 1.6 精度哲学:简单 ≠ 草率(由 Confidence Ledger 工程化)

- 初/中级用户不需绝对精度,但系统必须只在有把握时开口;把握不足则沉默或引导重拍,绝不误报。
- 竞品实证教训:Sportsbox 曾把 100°+ 肩转读成 <90°;"对经验不足的玩家,错误读数会让他们去追根本不存在的问题"。
- "沉默"不是价值观口号,而是系统设计——由 Confidence Ledger(3.3)强制执行。

## 第二部分:分层架构

平台按"行业无关的通用底座 + 可插拔行业包"解耦。

```
Layer 3 · 行业包 (Domain Pack) — 可插拔,行业特有
  关键事件定义 / 诊断特征 / 【核心】参考对比 / 三层基准 / Cue 映射
Layer 2 · 通用人体运动表示层 — 行业无关,全平台复用
  骨架关节点(RTMPose) / 归一化+时间对齐 / 通用运动分段
Layer 1 · 通用视频理解底座 (Video Profiler) — 行业无关
  视频"身份证":运动类型/人数/布局/机位/完整性/利手/机位画像
Layer 0 · Capture Coach / 拍摄质量控制 (v2.2 新增)
  上传后即时质量校验 +(移动端)拍摄中实时引导
```

Layer 0/1/2 行业无关,是平台通用资产;Layer 3 是唯一行业特有、可插拔的部分。换行业 = 换 Layer 3。

### 2.1 Layer 0 · Capture Coach(v2.2 新增)

很多分析失败应在拍摄阶段就避免。目标不是诊断动作,而是确保进入管线的视频足够可靠——减少误判、用户挫败和客服问题。
检查项:手机太近/太远、人未完整入镜、非 face-on、光线不足、球杆/手臂遮挡、无完整挥杆、左右手确认、帧率建议。
落地分两级:第一版(服务器端)上传后校验+引导重拍;移动端阶段拍摄中实时引导(依赖手机端轻量模型)。

### 2.3 Layer 3 核心机制:参考对比 (Reference-Based)

用学术验证过的"参考对比"取代旧的"单阈值判断"。
学术背书:CoachMe(ACL 2025)——比较学习者与专业 reference 在 temporal 与 physical 两维度差异,模拟教练思考,识别偏离并生成纠正。花滑比 GPT-4o 好 31.6%、拳击好 58.3%;同作者 2026 已扩展滑雪版。
含义:①参考对比是被顶会验证的正确路线;②通用大模型做精细指导会"说正确的废话",不能只靠 VLM;③"先学通用动作、再用少量数据适配" = 我们的三层架构。

### 2.4 VLM 与几何的分工(原则)

- VLM → Layer 0/1(读懂视频、粗判、生成解释与对话)。
- 几何 + 参考对比 → Layer 3(精细诊断,可审计)。
- 正确的 AI-native 姿态:CV 测量 → 规则/特征引擎诊断 → LLM/VLM 解释/选 cue/生成 drill/对话/复盘 → 教练/用户反馈校准。不是"把大模型接到视频上直接说 early extension"。
- VLM 已知不可靠项(须多证据交叉+人工复核):机位(随挥转身误判)、换装/拼接判断。

### 2.5 关键约束:不要过早抽象

现在按分层组织代码、保持边界清晰(为抽象埋线),但不现在设计通用行业包接口——留待第二行业验证。

## 第三部分:工程架构(证据链驱动)

### 3.1 双轨技术选型(v2.2 强化)

- **正式分析轨(服务器端精确诊断)**:RTMPose / RTMW / 自研特征。COCO 75.8% AP(远高于 MediaPipe ~35);CPU 90+ FPS;有移动端变体 RTMPose-s(骁龙865 70+ FPS);ONNX/TensorRT/ncnn 多端部署。
- **实时拍摄辅助轨(移动端取景引导/低端 fallback)**:MediaPipe / Apple Vision / 轻量模型。跨平台实时、工程成熟。
- 分割:SAM2(已验证,4点prompt后 mask 0.90-0.98)。
- 不是二选一,而是分工:精度用 RTMPose,实时取景用 MediaPipe。

### 3.2 工程分层(证据链结构)

Layer 0 Capture Coach → Video Profiler → Pose & Object Layer(body/opt hand/opt club/opt ball/seg/tracking)→ Event Layer(8阶段,每事件带 confidence)→ Feature Layer → Diagnosis Layer(只输出高置信;possible/likely/confirmed;低置信→重拍或沉默)→ Cue Layer(one issue→one cue→one drill→one verification)→ Learning Layer。

### 3.3 Confidence Ledger(置信度账本)(v2.2 新增 — 把"不误报"工程化)

每次输出 cue 前,系统必须形成可追溯的置信度账本:
video_quality / camera_angle / pose / phase_detection / reference_match / feature / diagnosis / cue_confidence / reason_if_silent。
产品据此决策(用户只看结果):能诊断→给 cue;不够准→引导重拍;局部可诊断→只说有把握的一项;完全不行→沉默。
注:项目一路已在各处算置信度(感知门、kp_guard、impact_conf、抑制规则),本账本是汇成统一的"说 or 不说"决策层。

### 3.4 3D-Ready Data Contract(3D 预留数据契约)(v2.2 新增 — 避免未来重构)

Phase 1 不承诺 3D 诊断,但数据结构从第一天预留(2D→3D 是必然趋势;不预留则将来痛苦重构):
body_keypoints_2d(必有)/ body_keypoints_3d_optional / camera_model_optional / world_coordinates_optional / club_keypoints_optional / hand_keypoints_optional / ball_flight_optional / launch_monitor_data_optional / imu_optional。
预留此契约,将来接传感器/球路/3D 不必推翻架构。

## 第四部分:数据战略(飞轮的燃料)

### 4.1 数据的三层身份

- 正确基准层(金标准):专业选手被明确标"正确"的示范 → 定义"什么是对"(唯一来源)。
- 错误参照层:同一专业选手示范的"错误" → 专业级干净错误样本;同人配对。
- 待测样本层:创始人及未来所有普通用户 → 测试引擎 + 校准业余正常波动范围。
关键纪律:创始人非专业选手,其挥杆只能作"待测样本",不能作"正确基准"。

### 4.2 同人对错配对(核心洞察,学术印证)

同一人先对后错,身体尺寸相同,两数据相减 → 个体差异抵消 → 剩纯粹"错误"信号。教学视频"同一专业选手,左对右错"分屏是理想素材。

### 4.3 GT 铁律(不可违反)

- GT 只来自人工视觉确认 + 明确意图申报;禁止引擎/AI 自造对错标签。
- 第三方对错标注(教练勾叉)只用于筛选素材/交叉验证,不作训练/校准真值。
- 意图预登记:引擎出结果前先人工登记"做的是什么"。

### 4.4 授权红线

- 公开知识可永久当"老师";公开数据集/他人视频不作产品参数或训练数据。
- 外部素材登记 DATA_PROVENANCE;上线前律师团队统一审核。

### 4.5 飞轮机制(护城河引擎)

1. 用户"确认"而非"标注":判断"识别准不准",外行可做,自动筛出失败帧。
2. 教练拖拽即标注(Coach Annotation Console):教练在产品内拖关节、修正 cue、选 drill,产出高纯度真值对。飞轮核心,非普通后台。
3. Cue Effectiveness Loop(v2.2 新增):记录每个 cue 是否让用户下一杆真的变好。比"诊断准确率"更是商业壁垒,最难被抄。
4. 数据↑→基准↑→cue 可信↑→用户↑→数据↑。

### 4.6 三层基准(v2.2 修订 — 取代"单纯以用户自己为基准")

修订说明:完全以用户自己为基准,他错的动作会被固化成"正常"。最新研究亦指出优秀表现存在个体差异,专业基准应是"带"而非"单一模板"。
1. Professional Reference Band(专业基准带):合理动作范围,非单一完美姿势。
2. Fault Boundary(错误边界):明显危害效率/稳定/安全的错误区。
3. Personal Baseline(个人进步轨迹):衡量是否朝目标方向改善。
不是"必须像某个 pro",也不是"你现在怎样都对",而是:专业带 + 错误边界 + 个人轨迹。

## 第五部分:竞品解剖与差异化

### 5.1 Sportsbox AI — "测量之王,把解读甩给用户"

$14.99–299/年,iOS;单摄像头出 3D、30+关节点。软肋(全是机会):①给数字不给指导;②学习曲线陡;③精度出错且对小白最危险(肩转 100°+ 读成 <90°);④预设范围基于巡回赛平均。

### 5.2 GOATY (GOATCode.ai) — 头号对标

$25/月;技术栈几乎相同(服务器端姿态、33关节点、face-on、8英尺)。已做到:实时语音教练、GOATScore 0-100+三子分、7个gate绿红灯、Tiger模型叠加、contextual bandit飞轮(1896人均+29.3)。结论:"简单分数+参考对比+飞轮"已被占位,不在高尔夫单点正面硬刚。

### 5.3 其他竞品格局

视频沟通型(OnForm/CoachNow);AI快速分析型(GolfFix/Sparrow/18Birdies,真实反馈:适合看明显问题、不适合fine tuning、相机没对齐则读数不准);传感器型(HackMotion/Arccos)。HackMotion 路径值得借鉴——"测量→理解问题→实时反馈+drill→追踪进步";我们做视觉版、无硬件版。

### 5.4 三个竞品都没占住的真空(靶心)

1. 真正可插拔的多行业平台(核心差异化)。
2. 真·初学者友好的三层基准(GOATY 用 Tiger 当靶,对小白够不着)。
3. 真正一眼看懂的视觉 cue + 下一杆闭环(竞品"简单"是数字或语音)。

### 5.5 差异化定位一句话

面向初/中级,以"下一杆闭环 + 一眼看懂的视觉 cue + 三层基准"降低门槛,底层是可跨行业复制的人体动作平台,靠专业教练高纯度飞轮 + cue 有效性追踪持续变准。

### 5.6 市场共识(印证决策)

纯手机摄像头是主流;月费 $15–30;face-on 是主流机位(印证选正面正确);常诊断错误多为身体大动作。

### 5.7 三个市场切口

1. 初/中级自助练习(要"下一杆怎么改",不要 50 参数)。
2. 教练提效工具(生成身份证/问题候选/before-after,拖拽修正贡献数据)。
3. 未来多运动平台(底层统一为 Cue Engine)。

## 第六部分:分阶段路线图

> 总原则:先跑通一个完整的下一杆闭环,再谈扩展。

### 阶段 0 · 地基收敛(当前,数周)

**破局点 1 · 终结单机裸奔 + 代码资产隔离防线(最优先,保命 + 平台埋线一起做):**
- **两仓库物理隔离**(比"单 repo 分目录"更彻底的埋线):
  - **Repo 1 `swingcue-core`**:纯平台通用底座(Layer 1 & 2)。只含通用视频处理、RTMPose 管线、时间对齐、归一化等。**绝不含任何高尔夫术语或规则**。
  - **Repo 2 `swingcue-golf-pack`**:可插拔高尔夫行业包(Layer 3)。以 git submodule 或依赖包形式引入 `core`。
  - 换行业时 `core` 完全不动,只换/加 pack。这是"不过早抽象、但结构先解耦"的落地方式。
- **异地备份**:两个 repo 均推 git 远程私库(单独建,勿混入旧 `swingcue` 文档库)。
- **.gitignore 铁律**:教学视频、SAM2/RTMPose 的 .pth/.onnx 模型权重,**绝不 commit 进 git**;放本地 `data/` 目录 + 云端网盘/NAS 备份。(现有 4.1G tar 过大,正是模型权重+视频混入所致。)

**破局点 2 · 盘活 137 段教学视频 = 建 Video Profiler 流水线:**
- **Layer 1 Video Profiler 建成独立模块**,整合已有能力,处理链:
  `感知门(是否高尔夫)→ 分屏切分(单人/左右分屏,识别勾叉对错标签)→ 方向解析/机位画像 → 生成统一 JSON 身份证(独立存档)`
- 用 137 段教学库跑全库体检,产出统一"身份证"表。
- **机位判定用几何交叉复核,不用 VLM 精细判**:用 kp_guard(有效性哨兵)+ RTMPose 关节点几何比例(双肩宽/胯步相对位置、球杆摆动轨迹)交叉复核 face-on vs DTL —— 比 VLM 靠谱(针对已踩过的"VLM 随挥误判机位"坑)。

**破局点 3 · 第一诊断目标的"收敛选举"(由数据定,不由主观):**
- 待 Video Profiler 跑完,统计 137 段中"正面 + 专业选手同人对错配对(左对右错分屏)"素材,**哪种错误数量最多、最能验证**,即作阶段 1 第一诊断目标。
- 预判(等体检表对号入座):若 **Sway/Slide(左右晃)** 最多 → 用现有肩宽归一化 + spine_lateral_tilt v0.1 雏形(正面易量化,身体两侧红绿边界线极直观);若 **Head Movement** 最多 → 用 head_ref v2(双耳中点)动态追踪。

**其余阶段0事项:**
- 素材家底盘清;代码按 Layer 0/1/2/3 重构(见第九部分资产搬迁映射表)。
- 数据按三层身份归类;定义并落地 3D-Ready Data Contract 的 schema 骨架。
- **确定度抑制的硬编码防线**:若 kp_guard 某帧置信度过低、或机位偏离 face-on 超安全阈值 → 直接触发引擎沉默(输出"建议调整拍摄角度,本次不予诊断")。Sportsbox"把 100° 读成 90° 误导小白"的前车之鉴绝不能在我们身上发生。
- (建议)试用 GOATY 免费版作为视觉 cue 设计参照。

### 阶段 1 · 第一个完整下一杆闭环(3–6 个月)
- 主机位:正面(face-on)。
