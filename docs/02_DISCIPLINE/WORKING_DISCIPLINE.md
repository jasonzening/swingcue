# 工作纪律 (Working Discipline)

> 这些是项目一路血泪换来的工作纪律。**不可绕过**。任何单点工作违反这些纪律时,以纪律为准。

## 1. 设计与执行分离

- 需要判断的**设计**由人(创始人 + Claude)定死成精确参数;实现代理(Hermes)**纯执行**,不自行发挥。
- 教训:多次事故源于让执行代理自己做判断(自造 GT、自行驳回异常、随意画图)。

## 2. 关卡制度 (Checkpoint)

- 任务带明确检查点(⛔),到点**停下等人工验收**,通过才继续。
- 禁止执行代理在架构决策点上自主继续。
- 新会话开工前**必须先确认当前任务来源**,禁止自取历史队列(TASK_QUEUE 已废弃)。

## 3. 先设计、后实现

- 任何特征/模块,**先写清定义**(测什么 / 哪个窗口 / 怎么判 / 关节点 / 阈值)并经拍板,**再交实现**。
- 教训:R2 曾因未先定义清楚,建成了测"转髋污染"的错误特征。

## 4. GT 铁律(见 `GT_IRON_RULES.md`)

- Ground Truth 只来自**人工视觉确认 + 明确意图申报**。
- **禁止引擎/AI 自造对错标签**。
- 第三方对错标注只用于筛选/交叉验证,**不作训练/校准真值**。

## 5. 不误报优于全覆盖

- 把握不足时**沉默或引导重拍**,绝不误报。
- 由 Confidence Ledger 工程化执行(见蓝图 3.3)。
- 前车之鉴:Sportsbox 把 100° 肩转读成 <90°,误导初学者去追不存在的问题。

## 6. 文档为王 + 异地备份

- 项目状态活在**文档和 git** 里,不依赖任何单机或单次对话记忆。
- 每次工作后 `git add . && git commit && git push`。
- 会话上下文过长(约 >300K)或连续工作超一天,**主动收尾、commit、开新会话**——上下文是消耗品。
- **模型权重/视频/依赖不进 git**(.gitignore 排除),单独备份到网盘/NAS。

## 7. 模块边界清晰(为平台化埋线)

- 即使现在只做高尔夫,也按三层(Layer 0/1/2/3)组织代码。
- 通用件(视频理解、骨架、归一化、事件分段框架、置信度账本)→ `core`。
- 高尔夫特有件(具体事件定义、解剖测量、对错标准、cue)→ `golf-pack`。
- 判断原则:"网球/理疗会不会也用到?会,归 core。"

## 8. 意图预登记

- 在引擎出结果**之前**,先把"这段做的是什么"人工登记存档(带时间戳)。
- 目的:防止引擎结果反向污染人的记忆,保证配对/验证独立可信。

## 9. 授权与合规(见 `DATA_PROVENANCE.md`)

- 公开知识可当"老师";公开数据集/他人视频不作产品参数或训练数据。
- 外部素材登记来源/授权范围/凭证;上线前律师团队统一审核。
